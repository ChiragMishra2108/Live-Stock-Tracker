# LIVE STOCK TRACKER AND UPDATER
#### Video Demo: https://youtu.be/JBXpfIPuGTM?si=HP0AAbDTpx_Vurv_
#### Description:
For my CS50 Finance project, I wanted to build something that went beyond the standard coursework: a live stock price tracker that monitors the market in real time and automatically sends an email alert when a stock drops below a price I choose. Typical CS50 problem sets rely on static pages where you submit a form, the page reloads completely, and you get a single snapshot of data. I wanted a system that runs continuously in the background without needing manual refreshes. To figure out how to set up this tracking system and trigger the automated mail alerts, I watched a guide on YouTube at https://youtu.be/OlVwN2THs3U. Because that video was high-level and focused on general concepts rather than Python web frameworks, I collaborated with AI to translate those abstract workflow patterns into actual Flask code that fits a web app.

A massive hurdle I faced right away was adding email features to a Python web server, which is never taught in CS50 lectures. To make this work, I had to import `Flask-Mail` along with its `Mail` and `Message` classes into my `app.py` file to handle outbound SMTP communication. When I first tried to connect the mail server, I kept running into frustrating "Connection Refused" errors because my app had no idea how to talk to external mail exchanges. Working alongside AI troubleshooting tools, I resolved this by setting up the correct network configurations: pointing outbound traffic to `smtp.gmail.com` on port 587 and explicitly enabling Transport Layer Security (`MAIL_USE_TLS = True`, `MAIL_USE_SSL = False`). On top of that, modern Google accounts block standard script logins due to security rules, so AI guided me through generating a specialized 16-character Google App Password and binding it securely to `MAIL_USERNAME` and `MAIL_PASSWORD` so the app could log in successfully.

Managing user data across continuous background requests created another complex debugging challenge. Initially, my background polling setup was firing `POST` requests without keeping track of any form payload, which resulted in a persistent `NoneType` error on the backend when the app tried to read the recipient's email address. With AI debugging support, I fixed this state-loss issue by changing how data was passed: instead of trying to stream the email address back and forth through front-end parameters on every single loop, I cached it securely inside Flask's built-in session storage using `session["tracking_mail"] = request.form.get("mail")` during the initial form submission at the `/track` route. This ensured the destination address remained safely available to background server routes without exposing sensitive details in client-side code.

For the front-end architecture inside `tracking.html`, I needed to dive into advanced asynchronous JavaScript for the auto-change live updating features, which is also well beyond standard CS50 requirements. I used concepts and promise structures from the asynchronous JavaScript tutorial found at https://youtu.be/E0UGGxd2DOo to understand how event loops, timing intervals, and background fetching work together. Since that educational resource originally implemented its logic using PHP instead of Python's Flask framework, I used AI to help me adapt and rewrite the snippet into a clean JavaScript implementation suited for my project. I built an automated polling loop using `setInterval` and `async/await` where the browser dispatches a background `fetch()` request every 500 milliseconds to query a custom JSON route.

This client-side script parses the incoming JSON data on every single tick and continuously checks a live condition: whether the current market stock price fetched from the API has dropped below my user-defined minimum threshold (`stock.price < min_price`). Once that threshold breach happens, the script quietly fires a secondary `POST` request to the `/mail` endpoint while simultaneously updating the DOM element (`priceElement.innerHTML`) to show live price updates on the screen in real time, completely getting rid of the need for a manual page refresh.

Finally, the backend ties all of these moving parts together through dedicated API and event routes. Protected by the `@login_required` decorator, the custom `/tracking/<symbol>` route executes the `lookup()` helper function to pull live market valuations and immediately serializes that pricing data into standard JSON strings using `jsonify` so JavaScript can process it easily. When the front-end triggers an alert condition, the `/mail` route safely extracts the cached recipient address from the session data, builds a structured `Message` object complete with custom subject lines and body text, and executes `mail.send(msg)` to transmit the alert straight to my inbox, successfully bridging the gap between static web design and real-time automation.

Building this project really pushed me past what we normally do in CS50 and taught me how to make a webpage update live instead of just reloading old data. Juggling background loops, saving user sessions, and setting up the email server was definitely a challenge, but seeing it all work together was totally worth it. Watching the stock price tick down on the screen and getting an email pop into my inbox right away felt amazing. It showed me how much cool stuff you can build when you combine Python, Flask, and JavaScript!
